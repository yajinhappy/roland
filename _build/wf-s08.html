ST-08 · T+1 정산 대사 & ERP 전표

1일일 대사 콘솔Reconciliation

매일 새벽 각 PG의 Settlement Report를 수집해 내부 승인 원장과 전수 대조한다. 어댑터의 fetchSettlementReport 가 수집 창구다.

기준결제일이 아니라 PG 정산일 — T+1 · T+2 · T+3 · T+7 · 월 2회가 섞여 있다
수집 형태CSV 파일 또는 API — PG마다 다름
진행 표시5단계 레일로 현재 어디까지 왔는지 노출 — 실패 시 멈춘 단계가 보인다
Tier 3 PG의 리포트 형태 미확인

Oneverse · GOC-PAY 등 파트너십형 게이트웨이가 정산 리포트를 어떤 형태로 주는지 확인되지 않았다. 어댑터 구현 가능 여부가 여기서 갈린다.

2대사 배치 즉시 실행배치 트리거

자동 스케줄과 별개로 운영자가 수동 구동한다. 리포트 재수신 · 불일치 재검증 시 사용.

3승인 vs 정산 집계지표

양쪽 건수와 금액을 나란히 보여 차이의 크기를 먼저 파악하게 한다. 일치율이 아니라 차이의 절대값이 조치 우선순위를 정한다.

3개 축트랜잭션 ID 일치 · 승인 금액 vs 정산 금액 · MDR 검증
환산집계는 USD 환산 · 상세는 원 통화 유지
4대사 결과 상태상태

3가지로만 분류한다. 애매한 중간 상태를 두면 아무도 처리하지 않는다.

5ERP 전표 전송내보내기

일치 건만 entity_id 별 회계 전표로 변환해 각 법인 ERP(SAP · NetSuite)로 전송한다. 불일치 건은 전송하지 않는다.
