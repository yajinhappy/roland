ST-07 · 환불 & CS 분쟁 처리

1환불 관리 마스터CS 데스크

오결제 · 서비스 장애 · 미지급 · 차지백을 한 목록에서 처리한다. 행마다 결제 채널의 Capability가 이미 판정되어 있어 담당자가 판단할 것은 사실관계뿐이다.

사유 코드입력 의무 — 자유 서술 금지. 통계와 정책 개선의 입력값
담당API 취소는 CS · 수기 송금은 해당 법인 재무팀으로 이관
색 구분붉은 행 = 자동 처리 불가 · 사람 손이 필요한 건
2지능형 분기 엔진엔진

두 번 갈린다. 첫 번째는 운영 모드(자동 · CS 검토), 두 번째는 PG Capability(API · 수기). 두 번째 판정은 사람이 바꿀 수 없다.

자동 조건미수령 · 미사용 · 7일 이내 — 3개 모두 충족
자동 절차게임 서버 실시간 검증 → PG 환불 API → 재화 회수 → 원장 역분개
우선순위Capability가 정책보다 상위 — 조건을 충족해도 채널이 불가면 수기로 간다
3원클릭 API 취소API 호출

PG 취소 API 호출에 성공하면 즉시 게임 서버로 POST /revoke 를 호출해 재화를 회수하고 원장을 역분개한다.

순서PG 취소 성공 후에 회수 — 순서가 바뀌면 재화만 사라진다
회수 실패재화 소모 시 계정 임시 동결 또는 잔여분 부분 환불
원장역분개로만 수정 · 원 전표는 불변 유지
/revoke 규격 미정

이 버튼이 호출할 API의 요청 · 응답 규격이 문서화되어 있지 않다. 부분 회수 · 잔여 부족 · 계정 동결의 반환 형태가 환불 승인 여부를 좌우하므로 Step 3에 등록 항목과 함께 확정 필요.

4재화 상태게임 서버 조회

환불 판단의 사실관계. 게임 서버에 실시간 조회해 미수령 · 미사용 · 일부 소모 · 전량 소모 4단계로 표기한다.

미수령우편함 대기 중 — 전액 환불 · 회수 불필요
미사용인벤토리 · 원장에 전량 존재 — 전액 환불 · 회수
일부 소모판단 기준 미정 — 잔여 수량을 표기하되 결정은 담당자에게 남는다
전량 소모가챠 소진 등 — 차지백 시 계정 정지 및 증빙 자동 제출
5수기 계좌 송금 워크플로우수동 데스크

API 취소가 원천 불가한 채널(MyCard · GASH · 편의점 현금)의 환불 경로. 유저 서류를 접수하고 해당 법인 재무팀 송금 목록으로 이관한다.

접수 서류통장 사본 · 신분증 — 전용 모달로 업로드
승인지사 재무팀 2차 검수 후 송금 완료 처리
사전 고지결제창에서 이미 「자동 환불 불가 · 수기 환불 시 수수료 발생」 동의를 받았다
개인정보송금 완료 후 보관 기간 만료 시 자동 파기 — 익명화 시점 별도 정의 필요
6미배송 건의 처리행 액션

배송 실패 격리 건은 환불이 아니라 수동 지급이 우선이다. 유저가 원한 것은 환불이 아니라 상품이기 때문.
