ST-03 · 게임 & Webhook 연동

1게임 연동 마스터그리드

퍼블리싱 대상 게임 서버의 표준 엔드포인트를 관리한다. 행 단위는 게임이 아니라 서버다 — 같은 게임이라도 서버마다 귀속 법인과 도메인이 다르기 때문.

통신HTTPS · TLS 1.3 의무
행 단위게임 × 서버 — 서버가 결제 귀속 법인을 결정한다
등록 전제Step 1의 법인이 먼저 등록되어 있어야 선택 가능
2신규 게임 등록모달

게임 코드 · 서버 목록 · 귀속 법인 · 콜백 URL을 등록하고 HMAC Secret Key를 발급받는다.

Secret Key최소 256비트 암호화 난수 자동 생성 — 발급 직후 1회만 평문 노출
등록 완료 조건Ping Test 성공 — 실패 상태로는 저장되지 않는다
3캐릭터 검증 엔드포인트REST API

결제 전 캐릭터 실존 여부와 계정 매핑을 확인한다. D2C 비로그인 결제의 유일한 신원 확인 수단이라 응답 지연이 곧 이탈이다.

요청game_id · server_id · character_name
응답character_guid · account_id · level · job_class
SLA500ms 미만 유지 필수
실패 처리미존재 캐릭터는 결제창 진입 자체를 차단. 서버 점검 중이면 점검 안내
4배송 Webhook 엔드포인트Webhook

결제 완료 후 게임 서버로 지급 신호를 보낸다. 결제 플로우에서 가장 자주 실패하는 지점이며, 실패 시 트랜잭션은 PAID_PENDING_DELIVERY로 격리된다.

멱등order_id 기준 1회 지급 보장 — 재시도가 중복 지급이 되면 안 된다
재시도Exponential Backoff 1 · 5 · 15 · 60분, 최대 10회 → 이후 CS 수동 지급 큐
응답result · in_game_mail_id · delivered_at
세 번째 API가 빠져 있다

환불 시 재화를 회수하는 POST /revoke가 Step 7 워크플로우에 등장하지만 요청 · 응답 규격이 문서화되어 있지 않다. 이 화면에도 등록 항목이 없다 — 2대 API가 아니라 3대 API로 확정 필요.

5HMAC 서명키보안

배송 웹훅의 위변조를 막는다. 허브가 페이로드에 서명하고 게임 서버가 검증한다.

헤더게임 서버가 검증할 헤더명을 하나로 고정해야 한다
교체무중단 교체를 위해 구/신 키 동시 유효 기간 제공
헤더명이 문서마다 다르다

설계서는 X-Gravity-HMAC-SHA256, 프로토타입은 X-Portal-Signature: sha256=. 게임팀 배포 전 확정 필수.

6실시간 Ping Test진단

실제 HTTP POST를 발송해 헬스체크한다. 응답 시간과 상태를 그리드에 상시 표기하고, 실패 시 알림을 보낸다.

주기정기 자동 + 수동 즉시 실행
실패 시알림 봇 연동 · 해당 서버 결제 진입 차단 검토
상태 3종정상 · 경로 상이(표준 규격 미준수) · 응답 없음
「경로 상이」를 상태로 둔 이유
문제응답은 오지만 표준 경로가 아니면 게임마다 별도 어댑터가 필요해진다
의도동작 여부와 규격 준수 여부를 분리해 표기 — 마이그레이션 대상을 눈에 보이게 남긴다
