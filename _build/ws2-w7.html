1상단 구조공통

웹샵 메인과 동일 배너 · 동일 위치. 메뉴바에서 [구매내역]만 활성한다.

배너전용 배너를 별도 등록하지 않는다 — 관리자 설정값을 그대로 따른다
탭 전환상단 구조가 유지되어 화면이 튀지 않는다
통화 표기과거 구매는 결제 당시 확정된 통화로 표기한다 — 웹샵에는 통화 선택 UI가 없다
2조회 기간필터

조건은 월 단위 하나다. 기간 · 상태 · 상품명 필터를 두지 않는다.

형식MM/YYYY · 달력 아이콘 클릭으로 월 선택
기본값당월
선택 시목록 갱신 + 1페이지로 초기화
MO달력을 바텀시트로 노출
3구매 내역 테이블목록

컬럼 7종. 행 클릭 시 이동하지 않는다.

컬럼No / 주문번호 / 구매 일시 / 구매 상품 / 구매 금액 / 영수증 / 결제 현황
정렬최신 건 상단 · 내림차순 고정 — 정렬 컨트롤을 두지 않는다
표기구매 일시 YYYY.MM.DD HH:MM(초 미표기) · 금액은 할인 적용 후
결제 현황구매 / 취소 / 결제 실패 / 처리 중 — 색으로 구분
빈 상태「구매 내역이 없습니다」
MO7컬럼 → 주문 1건 = 카드 1장. 상단 No · 주문번호 · 현황 / 중단 상품 · 일시 / 하단 금액 · 영수증
4영수증팝업

행별 아이콘 클릭 시 신규 창으로 발급한다.

구성주문번호 · 일시 / 상품명 / 금액 · 결제수단 / 수령 정보 / 판매자(사업자) 정보
수령 정보회원은 계정 · 비회원은 캐릭터
비활성취소 · 결제 실패 건은 아이콘 비활성
미결결제수단별 영수증 종류와 발급 주체는 PG 연동 정책 확인 후 확정

6계정 인증 영역분기

회원은 완료 표시, 비회원은 인증 입력이 들어간다.

회원✓ 계정 인증 완료 + 마스킹 계정 ID
비회원서버 + 캐릭터 ID 입력 후 [인증] — 인증한 캐릭터 구매만 조회
오류불일치 · 미존재 시 안내 · 시도 횟수 제한 적용
위치PC 우측 카드 · TABLET · MO는 리스트 상단 가로 바
확정 필요 사항

비회원 조회 인증 방식 — 원안은 서버 + 캐릭터 ID다. 결제 완료 화면은 주문번호 보관 안내 노출 여부를 조회 방식 확정과 함께 정하도록 두었다. 두 화면의 인증 방식을 같은 시점에 확정한다.

조회 가능 기간 상한 — 최근 12개월 등의 상한을 둘지.

영수증 발급 주체 — 결제수단별 영수증 종류(신용카드 매출전표 · 현금영수증)와 PG 제공 화면 연동 여부.
