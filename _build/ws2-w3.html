채널호출 방식복귀 처리

공통 규칙 — 어느 채널이든 결제창은 임베드 영역 안에서 열지 않는다. 대부분의 PG가 프레임 내 로드를 막고, 모바일은 팝업 차단 정책이 있어 화면 전체 전환 또는 별도 창이 표준이다.
현재 방식 채택 근거
4
게임 선택 셀렉터를 두지 않는 이유 형태 2 · 통합 웹샵 전용 주소은 링크로만 진입하며 상단은 라그나로크 포털 GNB만 노출한다. 지사와 게임은 진입 URL에 포함된다.
근거내용
법인 판정 전체 설계는 도메인 · 경로로 법인을 판정한다. 게임 코드만으로는 판정되지 않는다 — 동일 게임을 여러 지사가 서비스하면 상품표 · 가격 · 통화 · 결제수단이 결정되지 않는다. URL 경로에 지사 코드를 포함하면 기존 판정 구조가 그대로 적용된다
가격 정책 보호 지역 선택 UI가 없으므로 가격이 낮은 지역으로 우회하는 경로가 차단된다
로그인 전 판정 비회원 구매를 지원해야 하므로 로그인 없이도 법인이 확정되어야 한다. URL 경로는 로그인 여부와 무관하게 동작한다
설계 단순화 두 형태가 「호스트가 컨텍스트를 전달하고 웹샵이 렌더링한다」로 동일해진다. 관문 화면 · 지역 선택 · 미서비스 지역 기본값 설계가 불필요하다
확정 필요 3건
1 · 링크 규격 — 배포된 링크가 서비스 경로이므로 규격 변경 시 전량이 무효화된다. /{branch}/{game}으로 고정하고 어드민에 링크 생성기를 둔다.
2 · 대표 주소 진입 처리 — shop.gravity.com 진입 시 안내 페이지를 노출한다. 「게임 내 상점 또는 공식 사이트를 통해 접속해 주세요」 + 게임별 공식 사이트 링크.
3 · 캠페인 링크 — 글로벌 공용 링크가 필요하면 리다이렉트 전용 경로(/go/{game})를 두고 IP 기준으로 지역을 판정해 정식 경로로 넘긴다. 웹샵 본체에는 판정 로직을 두지 않는다.
추후 고려 — 웹샵 대표 주소에서 전 지사 게임을 리스트화해 게임을 선택할 수 있게 하는 방안. 도입 시 지역 판정 방식(IP 자동 · 명시 선택)과 지역 가격 노출 정책을 함께 확정해야 한다. 현 단계에서는 링크 진입만 지원한다.
두 형태가 필요한 이유

지사별로 유저 진입 경로가 다르다. 공식 사이트가 있는 지사는 기존 유입을 그대로 쓰고, 없는 지사는 통합 웹샵 전용 주소를 쓴다. 진입 경로마다 웹샵을 개별 구축하면 일원화 전제가 무너진다.

경계 위(호스트)만 분기하고 경계 아래(웹샵 본문)는 동일하게 설계했다. 두 형태 모두 호스트가 지사 · 게임 컨텍스트를 전달하고 엔진이 렌더링한다.

1형태 1 · 지사 사이트 내 웹샵하위 주소

지사 공식 도메인 하위 경로로 서비스한다. 유저에게는 지사 사이트의 일부로 보인다.

도메인ro.mygnjoy.com/shop — 동일 출처
상단 · 하단지사 오피셜 GNB · 푸터 · 테마가 그대로 감싼다
로그인상단은 지사 GNB의 지사 로그인이고, 웹샵 안 받을 캐릭터 영역의 [로그인]도 지사 로그인 창을 연다. 동일 출처라 지사 세션 쿠키가 자동 전송된다
계정 연계지사 인증을 이미 확보한 상태이므로 동의만 받고 포털 계정에 연결한다 — 추가 로그인 없음. 지사가 세션 검증 수단을 제공해야 성립한다. 상세는 웹샵/통합결제 기획 참조
적합게임 오피셜 사이트가 있고 기존 유입을 그대로 활용할 때
구축지사가 리버스 프록시 1회 설정 — 이후 개발 작업 없음
주의지사 GNB의 게임 BI와 웹샵 배너 로고가 중복돼 보일 수 있다 — 배너 숨김 옵션 검토
2형태 2 · 통합 웹샵 전용 주소링크 진입

본사 도메인에서 서비스하되 링크로만 진입한다. 지사 · 게임은 URL 경로에 포함된다.

URLshop.gravity.com/{branch}/{game} — branch는 9개 법인 코드의 소문자 표기(gv · gvc · ggl …), game은 게임 코드
진입 경로게임 클라이언트 · 지사 포털 · 공지 · 이벤트 링크. 전체 주소를 알면 직접 입력해도 열린다 — 차단하는 것은 대표 주소 진입이다
상단라그나로크 포털 GNB의 유틸 영역 — 로고 · 언어 · 로그인. 게임 선택 셀렉터 없음
계정 연계포털 로그인 후 해당 지사 연결 여부를 확인한다. 연결이 없으면 지사 인증을 한 번 더 받아 동의 후 포털 계정에 연결한다 — 연결 방향은 형태 1과 같다
법인 판정URL 경로의 지사 코드 — 로그인 여부와 무관하게 확정된다
적용 대상오피셜 사이트가 없는 지사 · 인게임 WebView 호출
구축본사 서버가 직접 서비스 — 지사 작업 없음
3채널별 결제창 호출4채널

두 형태 외에 지사 포털 탑업과 인게임 상점이 같은 결제창을 부른다.

웹 2종결제 세션 생성 후 화면 전체 전환 — 복귀 URL로 완료 화면
지사 포털경량 JS SDK로 팝업 · 모달 — HQPayment.open()
인게임내장 브라우저로 payment_url 호출 · 브릿지 · 딥링크로 종료 감지
공통임베드 영역 안에서 결제창을 열지 않는다 — PG 프레임 로드 제한 · 모바일 팝업 차단
정산채널이 달라도 법인 판정과 정산 경로는 동일하다
4현재 방식 채택 근거근거

게임 선택 셀렉터를 두지 않고 링크 진입으로 한정한 이유와 확정 필요 사항.

핵심 근거게임 코드만으로는 법인이 결정되지 않는다 — 동일 게임을 여러 지사가 서비스한다
