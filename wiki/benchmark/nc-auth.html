결론

원문

명칭은 「통합」이나 실제 동작은 통합 아님. 세 가지로 요약.

01
회원 통합이 아닌 레거시 계정계 폐기 · 본사 계정계로 흡수 이관 대등한 두 회원 DB의 병합이 아님. 북미 지사 자체 계정계를 폐기하고 본사 계정 DB로 레코드 이관. 방향성은 병합이 아니라 흡수.
02
동일인 복수 계정의 엔티티 병합은 명시적 포기 이관 완료 후에도 계정 2개 유지. 캐릭터 · 아이템 · 결제이력을 단일 계정으로 승계하는 절차 미존재.
03
채택 모델 — 단일 ID 네임스페이스 + 리전 속성 로그인 진입점은 하나로 수렴. 계정에 부여된 가입 국가가 노출 게임 · 결제 · 기능 권한을 분기.

충돌 계정 처리 — 설계의 핵심

PLAYNC의 유니크 키가 이메일. 동일 이메일이 양쪽 계정계에 존재하면 충돌이 필연. 원문 명칭은 conflicting account.

충돌 조건

NCWEST 계정과 기존 PLAYNC 계정(리니지2M · 퍼즈업 등 모바일, 또는 한국 등 타 지역 PC게임)을 동일 이메일로 생성한 경우. 이메일이 다르면 충돌 없이 자동 이관.

해법 — 사용자 셀프 해소

  • 자동 병합 미실시. 충돌 해소를 전적으로 사용자에게 위임
  • 로그인 실패 시 계정 상태 조회 링크로 유도. 전용 페이지 id.plaync.com/account-integration/issue
  • 이메일 입력으로 충돌 여부 진단. 비충돌이면 그대로 로그인
  • 충돌 시 현행 NCWEST 비밀번호 입력. 해당 비밀번호가 신규 계정으로 승계
  • NCWEST 계정을 신규 이메일에 재바인딩. 기존 이메일은 구 PLAYNC 계정이 계속 점유
  • 신규 이메일로 인증코드 수신 후 10분 내 입력 시 변경 확정
비가역

원문 경고 「This cannot be undone once you link your account to a new email address.」 기존 이메일은 이 시점 이후 구 게임 계정으로 동작하지 않음.

사전 회피책 병행 안내

PURPLE 출시 이전에 기존 PLAYNC 계정 이메일을 변경하면 충돌 자체가 미발생. 마이페이지 → 로그인 관리 → 이메일 변경.

리전 모델

계정은 단일 네임스페이스에 위치. 가입 국가가 서비스 권한을 분기.

·
로그인 진입점 「Global」 단일 구 NCA 서비스 계정은 전부 Global 취급. 신버전 PURPLE에는 Global 리전만 존재.
·
계정에 가입 국가 고정 · 노출 게임 카탈로그 결정 원문 「게임이 미노출이면 해당 게임을 지원하지 않는 국가로 계정을 등록한 것」. 게임 목록은 계정의 리전 속성에서 파생.
·
한국 등록 계정도 Global 로그인 시 한국 서비스 노출 원문 「한국에 등록된 PLAYNC 계정 보유 시 Global 리전 선택 후 로그인하면 한국 게임 서비스가 노출」. 레거시 PC 게임도 단일 인증으로 진입한다는 직접 근거. 계정 네임스페이스는 하나.
·
멀티플레이(다중 실행)는 동일 리전 계정 간에만 허용 브라질 계정으로 멀티플레이 시 추가 계정도 브라질 등록 필요. 이관된 구 NCWEST 계정은 US 취급이므로 병행 계정도 US 등록 필요. 리전이 인증뿐 아니라 기능 권한까지 분기.

2차 라운드의 중복 해소 절차

단계내용
1 · 중복 확인계정 상태 확인 페이지에서 중복 여부 조회. 로그인 웹페이지에서도 상시 확인 가능
2 · 본인 확인현행 비밀번호 입력. 비밀번호 분실 시 등록된 인증수단 (이메일 · 전화번호 등)으로 본인확인 경유
3 · 신규 식별자 설정신규 이메일 주소와 비밀번호 설정
4 · 자동 연결 해제변경 완료 시 중복 연결 계정을 시스템이 자동 해제. 연결이 해제돼도 원 계정 로그인은 정상 동작

출처 — PLAYNC 지원 FAQ 6565(이메일 중복) · 6567(자동 연결 해제).

소셜(3rd party) 계정 중복 — 2차 라운드에 신설

A
보유 계정 중 비중복 계정이 있는 경우 해당 계정으로 전환하도록 유도. 연결 계정 검증을 거쳐 변경.
B
연결 계정이 전부 중복이거나 연결 계정이 없는 경우 미사용 신규 이메일 또는 미사용 신규 소셜 계정으로 변경. 완료 후 중복 계정은 자동 연결 해제.

출처 — PLAYNC 지원 FAQ 6566.

패턴

불변 — 중복 해소 수단은 매회 「사용자가 식별자를 변경」. 자동 병합은 2차 라운드에서도 미도입.
개선 — 2차 라운드에서 ① 소셜 계정 중복 전용 해소 경로 신설 ② 비밀번호 분실 시 본인확인 경유 경로 추가 ③ 중복 연결 계정 자동 해제 ④ 안내 FAQ 사전 일괄 배포. 1차 라운드에서 노출된 결함 중 소셜 데드락과 비밀번호 의존은 실제로 보완됨.

Part 2

해석

본 사례를 모범 사례로 볼지 반면교사로 볼지가 갈리는 지점 정리.

축의 재설정

「신작은 통합 · 레거시는 분리」로 읽으면 원문과 불일치. 실제 분기 축은 신작 vs 레거시가 아니라 인증 레이어 vs 데이터 레이어.

인증 레이어 — 통합
  • 신작 · 구작 공통 PLAYNC 단일
  • 진입점은 PURPLE의 Global 하나로 수렴
  • 한국 등록 계정으로 Global 로그인 시 한국 서비스 노출
  • NCWEST 폐기 · NC Launcher 2 로그인 불가
게임 데이터 레이어 — 분리 유지
  • 캐릭터 · 아이템은 등록 리전 게임 서버에 잔류
  • 계정의 리전 속성이 접근 가능 서버를 결정
  • 한국 계정의 북미 서버 접속 불가는 계정계 분리가 아닌 리전 속성에 기인
  • 결제 · 정산도 리전 단위 분리
범위를 결정하는 축

통합 범위는 기술이 아니라 권역 · 법인별 계약 관계가 결정. 지분 100% 자회사(ArenaNet)도 미편입 · 퍼블리싱 권역(Gameforge)은 편입 불가 · 플랫폼 종속 신작(TL)은 계정계 자체가 외부. 지분율은 계정 구조를 보장하지 않음.

흡수 진행 기간과 신작 출시는 독립 진행. 출시 시점 규격 부재 시 해당 유저는 본사 IdP 범위 밖으로 확정.

핵심

계정계는 통합 · 게임 데이터는 미이전. 이 분리가 통합을 성립시킨 설계적 선택. 데이터까지 이전 대상으로 삼으면 20년치 레거시 DB 마이그레이션이 되며 실행 가능 범위를 벗어남.

성과와 미해결 지점

매끄러운 성공 사례 아님. 원문이 자체 기록으로 남긴 내용 기준.

✓
성과 — 사전 진단 도구와 유예 기간 통합 이전에 충돌 여부를 자가 조회하고 이메일을 미리 변경해 회피 가능하게 설계. 비충돌 계정은 로그인만으로 이관 완료. 다수 사용자에게 실제 무마찰.
✓
성과 — 데이터 미이전 캐릭터를 옮기지 않았으므로 대량 데이터 유실 사고 미발생. 계정 2개를 감수한 대가로 확보한 안전성.
✕
미해결 — 충돌 계정군의 CS 부하 Hotmail · Outlook 이관 실패, 원인 미상의 Account in Use · Abnormal Access 오류, 캐릭터 실종 문의, 결제 오류가 1년 이상 미해결 존치. 공식 가이드가 반복적으로 「Discord #game-support 티켓 개설」을 안내하는 상태.
✕
미해결 — 소셜 로그인 사용자의 구제 경로 부재 1차 라운드 한정 소셜 생성 계정은 이메일 변경 불가. 반면 충돌 해소 수단은 이메일 변경 단일. 해소 경로가 없는 조합이 구조적으로 존재. 2차 라운드(2025-10-22)에서는 소셜 계정 중복 전용 해소 경로가 신설되어 이 결함은 보완됨.
→
보완 — 2차 라운드의 학습 비밀번호 분실 시 본인확인 경유 경로, 중복 연결 계정 자동 해제, 안내 FAQ 8건 사전 일괄 배포. 다만 자동 병합은 끝까지 미도입이며 중복 해소 부담은 여전히 사용자 몫.
인용 시 주의

본 사례를 모범 사례로 인용 시 사실관계로 반박 가능. 정확한 위치는 「충돌 해소를 사용자에게 위임한 설계의 문제를 보여주는 반면교사」이며, 동시에 「데이터를 이전하지 않는 통합」이라는 실행 가능 전략의 실증 사례.

Part 3

시사점

라그나로크 포털 회원·인증 설계에 적용 가능한 항목과 동일 함정 회피 조건.

차용 항목

  • 엔티티 병합 미실시. NC 규모에서도 캐릭터 · 재화 · 구매이력 합산은 포기. 실행하려면 재화 합산 정책 · 중복 보유 아이템 · 정산 · 세무 귀속까지 전부 정의해야 하며 비용 급증. 계정은 복수로 두되 로그인 경험만 단일화.
  • 게임 데이터는 계정 UID에 결속. 계정계 교체가 데이터 이전 없이 완료됨. NC가 실제 채택한 방식이며, 「캐릭터는 구 계정에 잔류」라는 서술이 성립하는 근거.
  • 사전 진단 도구와 유예 기간 필수. 통합 이전에 사용자가 충돌 여부를 자가 확인하고 정리할 수 있게 하는 것 — NC가 충돌 회피 경로를 사전 제공한 항목.
  • 리전을 계정 속성으로 두고 서비스 카탈로그 · 결제 · 약관 분기. 단일 IdP + 리전 속성 조합은 실제 동작 검증됨.
  • 가입은 최소 정보로 개방. 국가 · 생년월일 · 이메일만 수집하는 간편가입이 글로벌 유입 허들을 낮춤. 법적 확인이 필요한 행위는 해당 행위 시점으로 이연.
  • 중복 해소 시 잔여 연결의 자동 정리. 식별자 변경 완료 시 중복 연결 계정을 시스템이 자동 해제하고, 해제 사실을 사용자에게 통지. NC 2차 라운드에서 도입한 방식으로, 사용자가 뒷정리까지 떠안지 않게 하는 최소 장치.
  • 안내 문서의 사전 일괄 배포. NC는 2차 라운드 개시일에 예상 문의 유형별 FAQ 8건을 동시 게시. 통합 공지와 안내 문서를 같은 시점에 여는 것이 CS 부하를 직접 좌우.

포털 적용안

위 항목을 라그나로크 포털 기준으로 정리하면 아래 형태.

01
계정 식별 구조 — UID 중심 불변 계정 UID를 최상위 키로, 이메일 · 소셜 · 전화번호를 하위의 교체 가능한 인증수단으로 결속. 어떤 인증수단도 PK가 되지 않게 구성.
02
데이터 귀속 — 게임 데이터를 UID에 결속 캐릭터 · 재화를 UID에 결속하면 인증 레이어를 교체 · 통합해도 데이터가 미이동. 통합 리스크를 인증 레이어 내부로 한정.
03
리전 — 속성으로 운용하되 변경 경로 개방 리전이 노출 서비스 · 결제 통화 · 약관 · 연령 정책을 결정하되 비가역 잠금은 미적용. 변경 시 재화 처리 규칙을 동시 정의.
04
통합 실행 — 사전 진단 · 유예 · 3단 해소 통합 공지 시점에 자가 진단 도구를 선행 개방하고 유예 기간 부여. 해소는 자동 매칭 → 셀프 → CS 대행 순의 단계 구성. 셀프 단계만 두면 NC와 동일한 결과.
05
퍼블리싱 경계 — 계약이 계정 구조를 결정 권역별 퍼블리싱 형태(직접 서비스 · 현지 퍼블리셔 · 플랫폼 종속)를 선행 확정해야 통합 범위가 결정됨. 아키텍처로 해소 가능한 영역이 아님.
