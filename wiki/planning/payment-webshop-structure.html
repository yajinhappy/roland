웹샵/통합결제 구조

본사가 통합 결제 모듈과 웹샵 템플릿을 단일 구성으로 제공하고, 각 지사는 자사 PG 키를 연동해 사용한다. 매출과 자금은 본사를 경유하지 않고 해당 지사에 직접 귀속된다.

대상 웹샵 템플릿 · 통합 결제창 · 지사 연동 기준 문서 웹샵/통합결제 기획 연계 문서 포털 메인 구조 · 랜드 회원·인증 설계 작성 2026-09-08
Part 1

시스템 구성

본사 제공 구성요소와 지사 도입 절차. 법인 · 게임 수 증가에 따른 추가 개발이 발생하지 않는 구조.

본사 제공 범위

구성요소구성 내용지사 설정 범위
웹샵 템플릿상품 목록 · 상품 상세 · 지급 대상 확인 · 선택 상품 · 결제 요청. 본사 서버에서 구동하고 리버스 프록시로 지사 도메인 하위 경로에 연결한다설정 없음 — 데이터 등록만
통합 결제창통화 · 결제수단 선택 및 결제 진행. 독립 URL 페이지 — 모달 · 팝업 · iFrame을 사용하지 않는다설정 없음
관리자지사 · 게임 등록 · 키 발급 · 상품 · 가격 · 점검 및 킬스위치 · 모니터링 · 환불 · 정산 대사자사 법인 범위로 제한

제공 구성요소는 3종이며, 법인 · 게임 수와 무관하게 재개발이 발생하지 않는다.

지사 도입 절차

지사 도입 작업은 관리자 등록 7개 항목과 리버스 프록시 1회 설정으로 완료된다.

상품 · 가격상품 목록 · 통화별 금액지사
 
location /shop/ {
    proxy_pass https://core-shop.gravity.com/shop/;
    proxy_set_header Host $host;                      # 지사 도메인 유지 전송
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

iFrame을 사용하지 않는다. 지사 공식 도메인 하위 경로로 서비스해 브라우저 기준 동일 출처(Same-Origin)를 확보하고, 지사 로그인 세션 쿠키가 /shop으로 자동 전송되도록 한다. proxy_set_header Host $host 누락 시 법인 판정이 성립하지 않는다.

Part 2

자금 · 매출

자금 수취 및 매출 귀속 경로와, 법인 간 거래가 혼입되지 않는 근거.

자금 흐름 및 매출 귀속

구분결정 방식
법인서버가 판정한다 — 형태 1은 Host 헤더, 형태 2는 URL 경로의 지사 코드. 미등록 도메인 · 미등록 경로는 로드 거부
결제 키해당 법인 머천트의 인증키. 서버에만 보관하며 프론트엔드는 보유하지 않는다
입금 계좌PG 계약 명의가 지사이므로 대금이 해당 법인 계좌로 입금
매출입금 계좌가 해당 법인이므로 해당 법인 매출로 계상. 본사 매출로 계상되지 않는다
세무각 법인이 소재 국가에서 납부 — 현행 구조와 동일

본사가 대금을 일괄 수취해 배분하는 경우 해외 수익이 본사 매출로 계상되고, 각 국가로 재송금하는 과정에서 세무 이슈가 발생한다. 계약 명의를 지사가 보유하는 근거다.

법인 간 거래 격리

법인은 도메인으로 확정되며, 지급 대상 확정도 해당 법인 범위 내에서만 가능하다.

비회원 — 캐릭터 인증
  • 서버 목록에 해당 법인 서버만 노출
  • 타 법인 캐릭터 ID 입력 시 인증 실패
  • 인증 완료 전 [결제하기] 비활성
회원 — 로그인
  • 해당 법인 게임 캐릭터만 조회
  • 캐릭터 미보유 시 결제 불가 — 빈 상태 안내
  • 랜드 계정에 해당 법인 GNJOY 바인딩이 있어야 조회 가능
캐릭터 기반 상품으로 한정한 근거

캐릭터 특정이 결제 선행 조건이므로 법인이 자동 확정된다. 로그인 없이도 매출 귀속이 유지되는 이유다. 회원 흐름에서는 회원·인증 설계의 「GNJOY 미바인딩 시 해당 지사 게임 조회 불가」 규칙이 동일한 역할을 수행한다.

단일 법인이 복수 국가를 운영하므로 통화가 복수로 구성된다 — 대만 법인은 TWD · HKD · MOP · USD 4종이다. 상품 12종 기준 48건이며 9개 법인 합계 200건 이상이 된다. 통화별 개별 입력 대신 가격 등급(Price Tier)으로 묶어 등급당 통화별 금액을 일괄 정의하는 방식 검토가 필요하다.

판매 채널별 적용 범위

상품 유형에 따라 판매 채널을 나눈다. 캐릭터 기반 상품은 회원 · 비회원 모두 웹샵에서 구매하고, 계정 기반 상품과 정액제 · 구독은 지사 포털 반영을 기본으로 하며 웹샵은 후속 과제로 둔다.

상품 유형구매 주체웹샵지사 포털채널 구분 근거
캐릭터 기반 상품
아이템 · 의상 · 소비 · 패키지		 회원 · 비회원 기본 가능 캐릭터 특정으로 지급 대상이 확정된다. 회원은 캐릭터 목록에서 선택하고 비회원은 캐릭터 인증으로 확정한다 — 비회원까지 구매가 성립하는 유일한 유형이다
계정 기반 상품
포인트 · 계정한정		 회원 후속 기본 지급 대상이 계정이므로 로그인이 전제다. 지사 포털은 로그인 계정이 곧 해당 법인 GNJOY 계정이어서 대상과 법인이 동시에 확정된다
정액제 · 구독 회원 후속 기본 갱신은 사용자 조작 없이 청구되므로 도메인 기준 법인 판정이 불가하다. 지사 포털은 계정이 법인을 확정해 해당 문제가 발생하지 않는다

채널을 가르는 기준은 로그인 필요 여부다. 웹샵은 비회원 구매를 지원해야 하므로 캐릭터 기반 상품으로 한정하며 — 회원 구매도 동일하게 지원한다 — 로그인이 전제인 상품군은 지사 포털에서 처리한다. 통합 결제창은 두 채널을 모두 지원하므로 결제 모듈 변경은 발생하지 않는다.

항목내용

구매내역 조회 기준지사 포털은 해당 법인 구매만 조회된다. 랜드 포털에서 통합 조회하려면 GNJOY 바인딩이 선행된다
