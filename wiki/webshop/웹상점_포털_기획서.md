## 1. 개요

### 1-1. 시스템 구조

- 관리자 설정(비로그인 구매 허용, 키비주얼, 카테고리, 노출 상품 등)이 **SDK를 통해 프론트엔드에 반영**되는 커스텀 웹몰 형태
- 카페24 · 메이크샵 · 웹솔라 같은 커스터마이징형 웹몰 구조를 지향
- 관리자 · 백엔드 기획은 본 문서 범위 외

### 1-2. 화면 구성

| No | 화면 | 설명 |
|---|---|---|
| 1 | 웹 상점 메인 | 상품 목록 + 결제 위젯 |
| 2 | 상품 상세 · 담기 | 카드 Hover / 상세 모달 |
| 3 | 결제 진행 | 권역별 PG 결제창 호출 |
| 4 | 결제 완료 | 수령 방식 안내 (쿠폰 / 우편함) |
| 5 | 구매 내역 | 단일 리스트 화면 |

### 1-3. 문서용 컨트롤

화면정의서 상단의 **화면 상태(비로그인 / 로그인)** 와 **권역(국내 / 해외)** 은 실제 UI 라벨이 아니라,
관리자 설정값에 따라 앞단이 어떻게 달라지는지 비교하기 위한 문서용 컨트롤이다.

해당 선택에 영향을 받지 않는 화면에서는 **두 버튼이 동시 선택 상태로 표기**되어, 보는 사람이 혼동하지 않도록 처리한다.

|---|---|---|
| 웹 상점 메인 | 개별 선택 | 개별 선택 |
| 상품 상세 · 담기 | 동시 선택 | 동시 선택 |
| 결제 진행 | 동시 선택 | 동시 선택 |

| 구매 내역 | 개별 선택 | 동시 선택 |

## 2. 공통 정책

### 2-1. 주문 유형 분기

비로그인 구매를 지원하므로 주문은 두 갈래로 나뉜다. **아이템 수령 방식이 다르므로 화면도 분리**한다.

| 구분 | 비로그인 주문 | 로그인 연동 주문 |
|---|---|---|
| 계정 귀속 | X | O |
| 캐릭터 인증 | **필요** (서버 + 캐릭터 ID + 인증번호) | 불필요 |
| 받을 캐릭터 선택 | 인증한 캐릭터로 고정 | **선택 없음** |
| 아이템 수령 | **쿠폰 번호 발급** → 게임 내 쿠폰 등록 | **계정 우편함 자동 발송** |
| 구매 내역 조회 | 주문번호 + 캐릭터 인증 | 계정 기준 목록 |

> 전제 : 게임 우편함은 **계정 단위**로 운영된다. 따라서 로그인 주문은 받을 캐릭터를 고르지 않고,
> 수령 캐릭터는 게임 접속 후 우편함에서 지정한다. (해당 배경 설명은 화면에 노출하지 않음)

### 2-2. 권역

| 항목 | 국내 KR | 해외 GL |
|---|---|---|
| 포털 | GNJOY (gnjoy.com) | GNJOY Global / GNJOY TW |
| 게임명 | 라그나로크 온라인 랜드 | Ragnarok Online: LAND / 仙境傳說 Online |
| 메뉴명 | 웹 상점 · 구매 내역 | Web Shop · Order History / 線上商城 · 購買紀錄 |

- 언어 선택 드롭다운 노출 11종, 실제 번역 제공은 **한국어 · 영어 · 일본어** 3종
- 언어 전환 시 게임명 · 통화 · 금액 표기 · 결제수단이 해당 권역 기준으로 함께 변경

### 2-3. 취소 · 환불

- 화면 내 [취소 요청] 액션은 **제공하지 않는다.** 취소 · 환불은 전량 **고객센터 접수** 기준
- 지급된 아이템은 사용 여부와 관계없이 게임 내에서 취소 · 환불 불가
- 결제 취소 시 미사용 쿠폰은 즉시 폐기, 사용 완료 쿠폰은 취소 불가

## 3. PAGE 1 — 웹 상점 메인

### 3-1. 구성

`1차 GNB` → `2차 GNB` → `키비주얼` → `상점 탭` → `카테고리` → `상품 리스트` + `결제 위젯(우측 고정)` → `푸터`

| No | 영역 | 정의 |
|---|---|---|
| 1 | 1차 GNB | GNJOY 포털 공통 헤더 · 언어 선택 · 로그인/계정 |
| 2 | 2차 GNB | 게임 BI + 게임 소개 / 커뮤니티 / 고객센터 / 웹 상점 |
| 3 | 키비주얼 | 1920 × 300 (핵심 요소는 중앙 1400 안에 배치) |
| 4 | 상점 탭 | 상품 구매(기본) / 구매 내역 / FAQ |
| 5 | 카테고리 | 추천(기본) / 전체 / 기간한정 / 패키지 / 재화 / 의상 / 소비 |
| 6 | 상품 리스트 | 카드형 그리드 · Hover 오버레이 |
| 7 | 캐릭터 인증(비로그인) / 아이템 수령(로그인) | 아래 3-2 |
| 8 | 선택 상품 | 담긴 상품 목록 · 수량 · 삭제 |
| 9 | 결제 수단 선택 | 아래 3-3 |
| 10 | 총 결제 금액 · 결제하기 | 필수 동의 체크 후 활성 |
| 11 | 구매 유의사항 | 아래 3-4 |
| 12 | 푸터 | 저작권 표기 |

### 3-2. 캐릭터 인증 / 아이템 수령 (⑦)

**비로그인**

1. 서버 선택
2. 캐릭터 ID 입력 → [인증번호 발송] (게임 접속 중인 캐릭터에게 시스템 메시지 발송)
3. 인증번호 입력 → [확인]

- 인증 완료 시 ①~③ 입력 영역이 `✓ 캐릭터 인증 완료 — 서버 / 캐릭터명` 표기로 대체
- 인증 완료 전 [결제하기] 비활성

**로그인**

- 캐릭터 드롭다운 **미제공**
- `계정 우편함으로 발송됩니다.` 안내만 노출
- 캐릭터 선택 단계가 없으므로 연결 캐릭터 유무와 무관하게 결제 진행 가능

### 3-3. 결제 수단 선택 (⑨)

좌우 **2열 박스**로 배치하며, 여기서 선택한 수단으로 PG 결제창을 호출한다.
**별도의 결제수단 선택 페이지는 두지 않는다.**

| 권역 | 노출 항목 |
|---|---|
| 국내 KR | 신용카드 · 간편결제 · 휴대폰 결제 · 계좌이체 |
| 해외 GL | PayPal · Xsolla · EBANX · Alipay · Razer Gold · PayNow |

- 국내는 **그룹 단위**로 묶어 노출하고, 카카오페이 · 네이버페이 등 개별 수단은 그룹 하위로 묶어 PG 결제창에서 선택
- 선택 항목은 테두리 강조, 미선택 시 [결제하기] 비활성
- 노출 목록은 관리자 설정값을 따르며 권역 전환 시 함께 변경

### 3-4. 구매 유의사항 (⑪)

| 상태 | 노출 문구 |
|---|---|
| 비로그인 | 구매한 아이템은 인증된 캐릭터 ID로 지급됩니다.<br>결제 완료 후 **쿠폰 번호가 발급**되며, 게임에서 쿠폰 등록 시 아이템이 지급됩니다.<br>지급된 아이템은 사용 여부와 관계없이 게임 내에서 취소 · 환불되지 않습니다. |
| 로그인 | 결제 완료 후 게임 내 우편함에서 수령 가능합니다.<br>지급된 아이템은 사용 여부와 관계없이 게임 내에서 취소 · 환불되지 않습니다. |

> 로그인 상태에서는 지급 대상 안내를 노출하지 않는다. 캐릭터 선택 절차가 없어 불필요한 정보이기 때문.

### 3-5. 총 결제 금액 · 결제하기 (⑩)

- 총 결제 금액 = 선택 상품 합계 (권역 통화 기준)
- **[필수] 구매 동의 체크** 미체크 시 [결제하기] 비활성
- 비활성 조건 : 캐릭터 미인증(비로그인) / 상품 미선택 / 결제수단 미선택 / 동의 미체크

## 5. PAGE 3 — 결제 진행

결제수단은 **웹 상점 결제 위젯에서 선택**하고, 선택한 수단으로 PG 결제창을 호출한다.
**결제창 내부 UI는 당사 구현 대상이 아니다.**

### 5-1. 국내 KR

```
[결제하기]
   ↓
결제 요청 — 선택한 그룹 코드 전달
   methodGroup : CARD
   region      : KR
   currency    : KRW
   amount      : 6,500
   ↓
서버가 권역 · 그룹 기준으로 PG 판단 → 결제창 주소 회신
   ↓
PG 결제창 (PC 팝업 / 모바일 · 태블릿 전체 전환)
   ↓
결제 결과 콜백 → 서버 검증(Webhook) → 아이템 지급
```

- 화면은 **어느 PG를 쓰는지 알지 못한다.** 라우팅은 서버가 담당
- 카드사 선택 · 할부 · 인증 등 결제창 내부 절차는 PG 화면에서 진행
- 수단 추가 · PG 교체 시 **서버 설정만 변경**되며 화면 수정 불필요

### 5-2. 해외 GL

- 당사 화면에서 PG사(PayPal · Xsolla · EBANX · Alipay · Razer Gold · PayNow)를 먼저 선택
- [Next] → 선택한 PG사의 결제창 호출
- 결제 금액은 하단 고정 바에 노출, 미선택 시 [Next] 비활성

### 5-3. 공통 — 결제 결과 처리

- 완료 · 취소 · 실패 모두 웹샵 결과 페이지로 자동 복귀
- 서버 검증(Webhook) 완료 후 아이템 지급
- 복귀 실패(앱 전환 후 이탈 등)에 대비해 구매 내역에서 결과 재확인 가능하도록 안내

## 6. PAGE 4 — 결제 완료

주문 유형에 따라 아이템 수령 방식이 달라, 화면을 두 갈래로 분리한다.

| No | 영역 | 비로그인 | 로그인 |
|---|---|---|---|
| 1 | 완료 메시지 | 쿠폰 번호가 발급되었습니다. 게임에서 쿠폰을 등록해 아이템을 수령해 주세요. | 구매하신 아이템이 게임 내 우편함으로 발송되었습니다. |
| 2 | 수령 방법 | **아이템별 쿠폰 번호** | `✉ 게임 내 계정 우편함 발송 완료` |
| 3 | 보관 안내 | 쿠폰 번호 · 주문번호 보관 안내 노출 | 미노출 |
| 4 | 주문 상세 | 주문번호 / 구매일시 / 상품 / 결제 금액 / 결제수단 / **수령 캐릭터** | 〃 / **수령 방법(계정 우편함)** |
| 5 | 액션 | [구매 내역] · [상점으로 돌아가기] | 〃 |

### 6-1. 쿠폰 번호 발급 (비로그인)

- 서버 검증 완료 시 **아이템별로 쿠폰 번호를 개별 발급**
- **수량이 2개 이상인 아이템은 수량만큼 발급**하고 `상품명 (1/2)` 형태로 구분 표기
  - 예 : 프리미엄 성장석 x1, 고급 스킬북 x2 → 쿠폰 3개
- 목록 구성 : `상품명 + 쿠폰 번호 + [복사]` 한 행, 상단에 총 발급 개수와 **[전체 복사]**
- [복사] 클릭 시 클립보드 복사 후 '복사되었습니다' 토스트
- [전체 복사]는 `상품명 : 쿠폰번호` 줄바꿈 형태로 일괄 복사
- 표기 형식 : 4자리 × 4블록 (예 `ABCD-1234-EFGH-5678`), 대문자 · 숫자 조합, 혼동 문자(O · 0 · I · 1) 제외
- 쿠폰 번호는 **이메일로도 발송**, 화면 이탈 후에는 구매 내역에서 재확인
- 1회 사용 · **재발급 불가**

### 6-2. 우편함 발송 (로그인)

- 서버 검증 완료 즉시 **게임 내 계정 우편함으로 자동 발송** — 별도 등록 절차 없음
- 수령 계정(마스킹 ID) 표기, 캐릭터명은 표기하지 않음
- 우편 보관 기간 · 미수령 처리는 게임 우편 정책을 따름

### 7-1. 조회 기간 (③)

- 조회 조건은 **월 단위 달력 선택 한 가지** — 기간 · 상태 · 상품명 필터 없음
- 표기 형식 `MM/YYYY` (예 09/2026), 기본값 **당월**
- 선택 즉시 목록 갱신, 페이지는 1페이지로 초기화

### 7-2. 구매 내역 테이블 (④)

| 컬럼 | 정의 |
|---|---|
| No | 조회 결과 기준 순번, 최신 건 상단 (내림차순 고정) |
| 주문번호 | `YYYYMMDD-일련번호` · 고객센터 문의 · 영수증 · 비로그인 조회의 식별 키 |
| 구매 일시 | `YYYY.MM.DD HH:MM` (초 미표기) · 권역별 현지 시간 |
| 구매 상품 | 상품명. 2건 이상은 '대표 상품명 외 N건' |
| 구매 금액 | 실제 결제 금액(할인 적용 후) · 권역 통화 |
| 영수증 | 아이콘 클릭 시 영수증 팝업 |
| 결제 현황 | 구매 / 취소 / 결제 실패 / 처리 중 |

- **행 클릭 시 이동 없음** (주문 상세 페이지 미제공)
- 내역이 없으면 빈 상태 안내 노출

### 7-3. 영수증 발급 (⑤)

- 행별 아이콘 클릭 시 **영수증 팝업(신규 창)** — 목록에서 바로 발급
- 구성 : 주문번호 · 구매 일시 / 상품명 · 수량 / 결제 금액 · 결제수단 / 수령 정보 / 판매자(사업자) 정보
- 결제 현황이 **취소 · 결제 실패**인 건은 아이콘 비활성

### 7-4. 계정 인증 (⑦)

| 상태 | 노출 |
|---|---|
| 로그인 | `✓ 계정 인증 완료` + 계정 ID — 계정 귀속 주문을 선택 월 기준 최신순 노출 |
| 비로그인 | 서버 + 캐릭터 ID 입력 후 [인증] — 인증한 캐릭터로 구매한 내역만 노출 |

- 비로그인 인증 전 목록은 빈 상태 안내
- 불일치 · 미존재 시 오류 안내, 인증 시도 횟수 제한 적용

## 8. TABLET / MO

PC의 **우측 고정 결제 위젯**은 좁은 화면에서 배치할 수 없으므로,
**하단 주문 바 + 펼침형 주문 정보 시트**로 대체한다.
TABLET(768) · MO(375)는 동일 구조이며 **상품 그리드 열 수와 여백만 다르다.**

### 8-1. 상품 구매 — 3개 상태

| 상태 | 내용 |
|---|---|
| STATE 1 · 진입 | GNB + 키비주얼 + 탭 + 카테고리 + 상품 그리드, 하단 주문 바 접힘 |
| STATE 2 · 스크롤 | 키비주얼 · 탭 · 카테고리는 스크롤로 밀려나고 **GNB만 상단 고정** |
| STATE 3 · 펼침 | 하단 바를 올리면 **주문 정보 바텀 시트** 오픈 (뒤 목록 딤 처리) |

### 8-2. 모바일 GNB

- PC의 1차 · 2차 GNB를 **단일 바로 통합** — `☰ / BI / MY` 3분할, 높이 54px, 배경 블랙
- 햄버거 : 전체 메뉴 드로어(게임 소개 · 커뮤니티 · 고객센터 · 웹 상점 · 언어 선택) 좌측 슬라이드
- MY : 비로그인 — 로그인 이동 / 로그인 — 마이페이지 시트
- 언어 선택은 GNB에서 제외하고 드로어 하단으로 이동

### 8-3. 하단 주문 바 · 주문 정보 시트

**접힘 (하단 고정)**

- 구성 : `[▲ 펼치기] + 선택 건수 · 총 결제 금액 + [결제하기]`
- 스크롤과 무관하게 항상 노출
- [▲] 또는 위로 스와이프 시 시트 오픈

**펼침 (바텀 시트)**

- 구성 : 선택 상품 목록 → 캐릭터 인증 / 아이템 수령 → 결제 수단 선택 → 총 결제 금액 · 필수 동의 → [결제하기]
- 상품 행 : 썸네일 · 상품명 · 단가 · 수량 조절(− / +) · [✕ 삭제]
- 최대 높이 화면의 80%, 초과 시 시트 내부만 스크롤하고 [결제하기]는 하단 고정
- 그립 바 · [▼ 접기] · 딤 영역 탭으로 닫힘

### 8-4. 상품 상세 — 전면 모달

PC의 Hover 오버레이 + 중앙 팝업은 터치 환경에서 사용할 수 없으므로 **전면(Full screen) 모달**로 대체한다.

- 카드 터치 영역 분리 : **이미지 · 상품명 · 가격 = 상세 모달** / **[담기] = 바로 추가**
- 구성 : 헤더(← / ✕) → 이미지(정사각) → 상품명 · 설명 · 효과 · 가격 세로 스택 → 하단 고정(수량 + [담기])
- 기기 뒤로가기 제스처도 닫기로 처리
- 태블릿도 동일하게 전면 처리 (좌우 여백을 둔 팝업형 미적용)

### 8-5. 결제 진행

- 모바일 브라우저는 **팝업 차단 정책**으로 새 창 호출이 불안정 → **동일 창 전체 전환(리다이렉트)**
- 전환 전 주문 정보를 서버에 선저장하고 **주문번호 발급 후 이동**
- 이동 중 로딩 상태 노출, [결제하기] 중복 탭 차단
- 해외는 PG사 목록을 **세로 리스트**로 전환

### 8-6. 결제 완료 · 구매 내역

| 화면 | 모바일 대응 |
|---|---|
| 결제 완료 | PC와 정책 동일, 세로 스택. 쿠폰은 `상품명 → 코드 → [복사]` 세로 카드형. 주문 상세는 **아코디언** |
| 구매 내역 | 7컬럼 테이블 → **주문 1건 = 카드 1장**. 상단 `No · 주문번호 · 결제 현황` / 중단 `상품명 · 구매 일시` / 하단 `금액 · [영수증]` |

- 구매 내역의 계정 인증은 우측 카드 대신 **리스트 상단 가로 바**
- 월 선택 달력은 **바텀 시트**로 노출
- 페이징 번호 블록은 5개 단위로 축소

## 9. 통합결제 설계 방향 (GOAL)

> 상세 근거는 `웹샵_결제_벤치마킹.html` 7장 참조

### 9-1. 목표

권역마다 결제수단은 다르지만, **웹상점 화면과 연동 코드는 하나로 유지**한다.
개별 수단을 나열하지 않고 **그룹 단위로 묶어 노출**하고, 실제 처리는 **그룹 + 수단 코드를 전달**해 서버가 PG로 라우팅한다.
결과적으로 **권역이 늘어도 추가되는 것은 데이터뿐, 화면과 분기 로직은 그대로**인 구조를 만든다.

### 9-2. 벤치마킹에서 확인된 문제

4사 모두 결제수단을 **평면 리스트로 나열**하고 있어, 수단이 늘어날수록 화면과 분기가 함께 늘어나는 구조였다.

| 대상 | 관찰 | 시사점 |
|---|---|---|
| NC | NCPAY 우선 + 일반결제 병행, 신용카드 선택 시 카드사 16종 펼침 | 2뎁스 구조는 유효. 자체페이가 없으므로 최상단은 '최근 사용 수단'으로 대체 |
| 넥슨 | 캐시 → FC 환전 2단계, 충전 화면에 수단 9종 평면 나열 | **재화 2단계 구조 미채용** — 환불 시 역순 처리로 복잡도만 증가 |
| 블리자드 | 같은 브랜드인데 KR은 로컬 간편결제 10종+, EU는 세금 포함 총액 우선 노출 | **권역 차이를 화면이 아닌 데이터로 흡수**해야 한다는 직접 근거 |
| EA · 에픽 | 카드 · PayPal · BNPL · 지갑을 한 뎁스에 병기 | 성격이 다른 수단이 섞이면 선택 비용 증가 → 그룹 → 수단 2뎁스 |

### 9-3. 결제수단 그룹 체계

화면에 고정되는 것은 **그룹**이고, 그룹 안의 **수단 목록만 권역별로 달라진다.**

| 그룹 코드 | 노출명 | 국내 KR | 해외 GL |
|---|---|---|---|
| `EASY_PAY` | 간편결제 | 카카오페이 · 네이버페이 · 토스 · 페이코 · SSG페이 | PayPal · Apple Pay · Google Pay · Alipay |
| `CARD` | 신용카드 | 국내 카드사 (신한 · 삼성 · BC · 국민 등) | Visa · Mastercard · AMEX · JCB |
| `MOBILE` | 휴대폰 결제 | 통신 3사 휴대폰 결제 | Carrier Billing (지원 국가 한정) |
| `BANK` | 계좌 결제 | 계좌이체 · 무통장입금(가상계좌) | SEPA · iDEAL · Sofort |
| `PREPAID` | 선불 · 상품권 | 문화상품권 · 해피머니 · 티머니 | PaySafeCard · Razer Gold |

**운영 규칙**

- 그룹은 **전 권역 공통 코드**로 고정, 하위 수단 목록만 권역 설정값으로 주입
- 해당 권역에 수단이 하나도 없는 그룹은 **화면에서 자동 미노출**
- 노출 순서는 권역별 재정의 가능
- PayPal은 별도 그룹으로 빼지 않고 **해외 EASY_PAY 그룹의 최상단 수단**으로 배치
- 자체 지갑 · 게임 재화 구조는 **현 단계 미채용** — 도입 시 `WALLET` 그룹 추가로 확장

### 9-4. 동작 방식

웹상점 화면은 **결제사(PG)를 직접 상대하지 않는다.** 화면은 고객이 고른 결제수단이 무엇인지만 알려주고,
어느 결제사로 보낼지는 **서버가 판단**한다.

1. 고객이 선택 — 웹상점에서 '간편결제' 선택
2. 화면 → 서버 — 주문 금액 · 권역 · 고른 결제수단만 전달
3. 서버가 판단 — 권역과 수단에 맞는 결제사 선택
4. 결제창 노출 — 해당 결제사 결제창으로 이동
5. 서버가 확인 — 결제사 결과를 받아 검증 후 아이템 지급

> **비유** — 지금까지는 고객이 은행 창구를 직접 찾아가는 방식이라, 은행이 늘 때마다 안내판(화면)을 새로 만들어야 했다.
> 통합결제는 안내 데스크를 하나 두는 것이다. 고객은 "카드로 낼게요"라고만 말하고, 어느 은행으로 보낼지는 데스크(서버)가 판단한다.
> 은행이 바뀌거나 늘어나도 **고객이 보는 안내판은 그대로**다.

### 9-5. 기대 효과

| 항목 | 지금 방식대로 가면 | 통합결제로 가면 |
|---|---|---|
| 결제수단 추가 | 수단마다 화면 수정 · 검수 · 배포 | **설정에서 수단 추가로 끝.** 배포 불필요 |
| 신규 국가 오픈 | 국가별 결제 화면 별도 개발 | **수단 목록 · 통화만 등록**하면 같은 화면으로 오픈 |
| 결제사 교체 · 추가 | 화면부터 재개발 (수수료 협상력 약화) | **서버 설정만 변경** → 결제사 비교 · 교체 가능 |
| 운영 · 지표 | 국가마다 수단명이 달라 매출 비교 곤란 | **공통 기준**으로 국가 간 실적 비교 |
| 장애 대응 | 특정 결제사 장애 시 해당 국가 결제 중단 | 서버에서 **다른 결제사로 우회** 가능 |

### 9-6. 화면 반영 원칙

- 결제 위젯에는 **그룹 버튼만 2열 박스로 고정 노출**, 하위 수단은 PG 결제창에 위임
- 노출 그룹 · 순서 · 하위 수단은 **관리자 설정값**으로 제어
- 해외는 **세금 포함 최종 금액을 결제수단보다 먼저 고정 노출**
- 결제 실패 · 이탈 시 **선택했던 그룹을 유지**한 채 복귀
